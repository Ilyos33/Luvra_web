# LUVRA — платформа сайта

Полноценный сайт LUVRA: главная страница, каталог с фильтром по категориям и
защищённая админ-панель для управления товарами и категориями.

## Стек

- **Backend:** Node.js + Express
- **База данных:** SQLite (файл `db/luvra.db`, создаётся автоматически)
- **Авторизация:** JWT в httpOnly-куке + bcrypt для паролей
- **Загрузка изображений:** multer (jpg, png, gif, webp, до 5 МБ, до 6 файлов на товар)
- **WYSIWYG для описаний:** Quill.js (подключается через CDN)
- **Витрина (Главная/Каталог):** собственный CSS в фирменном стиле LUVRA
- **Админка:** Tailwind CSS (через CDN, без сборки)
- **Мультиязычность:** JSON-файлы локализации (`public/locales/ru.json`, `uz.json`)

## Быстрый старт (локально)

Понадобится [Node.js](https://nodejs.org) версии 18 или новее.

```bash
cd luvra-platform
npm install
cp .env.example .env
```

Открой `.env` и заполни:
- `JWT_SECRET` — длинная случайная строка. Сгенерировать:
  ```bash
  node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
  ```
- `ADMIN_RECOVERY_KEY` — секретный код восстановления пароля (сохрани его в надёжном
  месте, например в менеджере паролей — это твой "запасной ключ" от админки):
  ```bash
  node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
  ```
- `ADMIN_USERNAME` и `ADMIN_PASSWORD` — логин/пароль первого администратора.

Создай администратора:

```bash
npm run seed
```

Запусти сервер:

```bash
npm start
```

Сайт откроется на `http://localhost:3000`, админка — на `http://localhost:3000/admin`.

**После первого запуска seed-скрипта убери `ADMIN_PASSWORD` из `.env` или замени его
на случайную строку** — пароль в этом файле нужен только один раз для создания
аккаунта и не должен храниться открытым текстом постоянно.

## Как это работает

### Каталог и фильтр по категориям
Каталог изначально пуст — товары добавляются только через админ-панель.
На странице `/catalog` кнопки-категории подгружаются из `/api/categories`,
при клике товары фильтруются запросом `/api/products?category=slug`.

### Многоязычность
Все текстовые строки интерфейса лежат в `public/locales/ru.json` и `uz.json`.
Разметка вида `<span data-i18n="hero.title">` автоматически заполняется текстом
на выбранном языке (`public/js/i18n.js`). Выбор языка сохраняется в localStorage
браузера и не сбрасывается при переходе между страницами.
Название и описание каждого товара хранятся в базе на двух языках сразу
(`name_ru`/`name_uz`, `description_ru`/`description_uz`) — их заполняет админ
при добавлении товара.

### Восстановление пароля без email
Чтобы не зависеть от настройки почтового сервера, восстановление пароля работает
через секретный код (`ADMIN_RECOVERY_KEY` в `.env`) — это как запасной код для
входа. На странице `/admin/recover` нужно ввести этот код, логин администратора
и новый пароль. **Если позже понадобится восстановление по email** — это можно
добавить, подключив SMTP (например, через `nodemailer`) — дай знать, помогу.

## Безопасность — что уже сделано

- Пароли хранятся только в виде bcrypt-хэша (12 раундов), никогда в открытом виде.
- Вход защищён JWT-токеном в httpOnly-куке (недоступна для чтения из JS в браузере,
  что защищает от кражи токена через XSS).
- Ограничение частоты запросов (`express-rate-limit`) на вход и восстановление пароля —
  защита от подбора пароля.
- Проверка заголовка `Origin` на запросах, которые меняют данные — защита от CSRF,
  работает вместе с `SameSite=Strict` у куки.
- Все запросы к базе идут через подготовленные выражения (`better-sqlite3`
  использует параметризованные запросы) — классическая SQL-инъекция здесь не сработает.
- HTML из WYSIWYG-редактора очищается на сервере (`sanitize-html`) перед сохранением —
  защита от XSS через описание товара.
- Загружаемые файлы проверяются по MIME-типу и расширению, ограничены по размеру
  (5 МБ) и переименовываются в случайные имена — оригинальное имя файла никогда
  не используется на диске.
- Заголовки безопасности выставляет `helmet` (Content-Security-Policy и другие).

### Что нужно настроить отдельно — HTTPS

HTTPS — это не код приложения, а настройка сервера/хостинга. Сам Express отдаёт
обычный HTTP; шифрование обычно включает:
- **Хостинг с готовым SSL** (Render, Railway, большинство shared-хостингов) — просто
  привязываешь домен, сертификат подключается автоматически.
- **VPS** — ставишь Nginx или Caddy перед приложением и получаешь бесплатный
  сертификат через Let's Encrypt (Caddy делает это вообще одной строкой конфига).
- **Cloudflare** — включаешь проксирование домена через Cloudflare, HTTPS
  включается "из коробки" без настройки сервера.

В `server.js` уже включено `app.set('trust proxy', 1)` — это нужно для корректной
работы за любым из этих вариантов.

## Деплой на сервер (кратко)

1. Скопируй папку проекта на сервер (кроме `node_modules`, `.env`, `db/luvra.db`, `uploads/*`).
2. `npm install --production`
3. Создай `.env` на сервере со своими значениями.
4. `npm run seed`
5. Запусти через процесс-менеджер, чтобы сервер перезапускался при сбоях и после
   перезагрузки сервера, например [PM2](https://pm2.keymetrics.io/):
   ```bash
   npm install -g pm2
   pm2 start server.js --name luvra
   pm2 save
   pm2 startup
   ```
6. Настрой реверс-прокси (Nginx/Caddy) с HTTPS перед приложением, как описано выше.

## Важно: тексты и номера телефонов нужно проверить

При сборке этой версии я не смог заново открыть твой GitHub-репозиторий (он не
находится через поиск, а прямой повторный доступ к уже прочитанному ранее файлу
в этой сессии технически ограничен). Поэтому:
- Тексты на главной странице (заголовок, описание, "Почему LUVRA", "О бренде")
  написаны заново в похожем стиле и смысле, но **не скопированы дословно** из
  твоего оригинального сайта.
- Номера WhatsApp в разделе "Контакты" — **временные примеры**, их обязательно
  нужно заменить на настоящие номера LUVRA.

Проще всего поправить это самому: открой `public/index.html`, найди блоки
`hero-text`, `about-text` и `contact-box` и впиши точные формулировки и номера
с твоего действующего сайта.
